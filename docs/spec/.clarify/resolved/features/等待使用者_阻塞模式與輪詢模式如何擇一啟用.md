# 釐清問題

阻塞模式與輪詢模式如何擇一啟用？

# 定位

Feature：等待使用者。§7.7 / §14 Q1：若 Qoder 對阻塞 tool call timeout 不可調，show_step 改立即回傳並加 wait_for_user。未寫產品要支援雙模式還是 hackathon 只做一種。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | MVP 只做阻塞 show_step；不做 wait_for_user |
| B | MVP 只做非阻塞 show_step + wait_for_user 輪詢 |
| C | 兩種都做，用設定或環境變數擇一（需定預設） |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

等待使用者整份 Feature 是否納入驗收、Session SHOWING 時能否再呼叫 tool、顯示步驟並發。應先於「各狀態允許哪些工具」。

# 優先級

High
- High：阻礙核心功能定義或資料建模

# 解決記錄

- **回答**：A - MVP 只做阻塞 show_step；不做 wait_for_user（使用者重選後確認）
- **更新的規格檔**：docs/spec/erm.dbml、docs/spec/features/顯示步驟.feature、docs/spec/features/等待使用者.feature
- **變更內容**：show_step 畫出 overlay 後阻塞直到完成或逾時；MVP 不提供 wait_for_user
