## 4. 名詞小抄

| 名詞 | 白話解釋 |
|---|---|
| **uv** | 這個專案用的 Python 套件／環境管理工具。你不用自己建 venv，也不用 `pip install`，全部用 `uv ...`。 |
| **`uv sync`** | 讀 `pyproject.toml`，建立 `.venv`、裝好所有依賴、產生 `uv.lock`。 |
| **`uv run <指令>`** | 在 `.venv` 裡跑那個指令。等同「先 activate 再執行」，但不用真的 activate。 |
| **`.python-version`** | 一行文字檔，寫著這個專案要用哪個 Python 版本。uv 會照它挑直譯器。 |
| **`uv.lock`** | 鎖住每個套件的確切版本與雜湊。**要 commit**，這樣別人 `uv sync` 會裝到一模一樣的東西。 |
| **`[dependency-groups]`** | `pyproject.toml` 裡放「開發時才需要的套件」的地方（pytest 之類）。`uv sync` 預設會裝 `dev` 這一組。 |
| **`[tool.pytest.ini_options]`** | pytest 的設定寫在 `pyproject.toml` 的這一段，不用另外開 `pytest.ini`。 |
| **marker** | 貼在測試上的標籤。我們會註冊一個 `browser` marker，之後用 `-m "not browser"` 跳過會開瀏覽器的測試。 |
| **`conftest.py`** | pytest 會自動載入的檔案，放共用 fixture，測試檔不用 import 就能用。 |
| **fixture** | 「共用材料」。用 `@pytest.fixture` 定義一個函數，測試把它的名字寫在參數上就會拿到回傳值。 |
| **`anyio`** | 一個讓 async 程式可以跑在不同後端（asyncio / trio）的套件。MCP SDK 用它，它也附了一個 pytest plugin，讓我們可以寫 `async def test_...`。 |
| **`@pytest.mark.anyio`** | 貼了這個標籤的 async 測試，anyio 的 plugin 才會真的去跑它（否則 pytest 只會警告「你回傳了一個沒有被 await 的協程」）。 |
| **`anyio_backend` fixture** | 告訴 anyio 要用哪個後端。我們固定回 `"asyncio"`。 |
| **in-memory client** | 不開子行程、不走 stdio，直接把 `MCPServer` 物件交給 `Client(...)`，在同一個 process 裡對話。測試專用。 |
| **`structured_content`** | MCP tool 回傳結果的「結構化」那一份（給程式讀的 dict）；另一份 `content` 是給模型看的文字。 |
| **smoke test（煙霧測試）** | 最粗淺的「有沒有冒煙」檢查：不驗細節，只確認東西接得起來、開得起來。 |

## 6. 介面約定

### 6.1 用到（現有骨架已經提供）

```python
# showme/server.py（已存在）
from mcp.server import MCPServer
mcp = MCPServer("showme", instructions="...")

@mcp.tool()
async def start_tutorial(url: str, goal: str) -> dict: ...
@mcp.tool()
async def inspect_page(session_id: str) -> dict: ...
@mcp.tool()
async def show_step(session_id: str, uid: str, instruction: str, kind: str,
                    step_index: int, step_total: int,
                    expect_text: str = "", timeout_s: float = 120) -> dict: ...
@mcp.tool()
async def end_tutorial(session_id: str, summary: str) -> dict: ...

# showme/__main__.py（已存在）
def main() -> None:
    mcp.run(transport="stdio")
```

### 6.2 提供（給後面所有篇章）

```python
# tests/conftest.py
@pytest.fixture
def anyio_backend() -> str: ...        # 固定回 "asyncio"
```

```toml
# pyproject.toml：註冊了一個 marker
markers = ["browser: 會開真的瀏覽器（headless Chromium），用 -m 'not browser' 跳過"]
```

之後每個 async 測試檔的開頭都會寫 `pytestmark = pytest.mark.anyio`；每個會開瀏覽器的測試都會貼 `@pytest.mark.browser`。

### 6.3 查證過的官方 API（Context7，`/websites/py_sdk_modelcontextprotocol_io_v2`）

| 事實 | 來源 |
|---|---|
| in-memory 測試寫法：`from mcp import Client`，然後 `async with Client(mcp) as client:` | <https://py.sdk.modelcontextprotocol.io/v2/client/transports> |
| pytest 範例就是用 `@pytest.fixture def anyio_backend(): return "asyncio"` ＋ `@pytest.mark.anyio` | <https://py.sdk.modelcontextprotocol.io/v2/get-started/testing> |
| `await client.list_tools()` 回傳 `ListToolsResult`；裡面是 `.tools`，每個 tool 有 `.name`、`.title`、`.description`、`.input_schema` | <https://py.sdk.modelcontextprotocol.io/v2/api/mcp/client/client> |
| tool 回傳 **`dict[str, ...]`（字串鍵的字典）時，`structured_content` 就是那個 dict 本身，不會被包成 `{"result": ...}`**；只有回傳純量（str / int / float / bool / None）、list、tuple 時才會被包成 `{"result": ...}` | <https://py.sdk.modelcontextprotocol.io/v2/servers/structured-output> |
| tool handler 丟例外 → client 收到 `is_error=True` 的結果（所以我們永遠 `return` dict） | <https://py.sdk.modelcontextprotocol.io/v2/servers/handling-errors> |
| `mcp.run(transport="stdio")`：transport 參數在 `run()`，不在建構子 | <https://py.sdk.modelcontextprotocol.io/v2/run> |
| Playwright 瀏覽器安裝與 `channel="chrome"` | <https://playwright.dev/python/docs/browsers> |

> ⚠️ 我們四個 tool 的回傳型別註記是**沒有參數的 `dict`**（不是 `dict[str, object]`）。官方文件只明講了 `dict[str, ...]` 的行為，沒有明講裸 `dict`。Step 10 已經實測過了，答案是**第三種**：裸 `dict` 產不出 output schema，所以 `structured_content` 是 `None`（不是裸 dict，也不是 `{"result": ...}`）。詳見 Step 10。

```toml
dependencies = [

```

新加的兩段各在做什麼：

| 設定 | 意思 |
|---|---|
| `dev = ["pytest>=8", ...]` | 開發時才要的套件。`uv sync` 預設會裝 `dev` 這一組；正式安裝（`pip install showme`）不會帶到它們 |
| `pytest-timeout` | 提供 `timeout = 60` 這個設定：任何一條測試跑超過 60 秒就強制失敗。A12 會寫「阻塞等待」的測試，萬一寫錯造成永遠等下去，這條設定會救你 |
| `anyio>=4` | 提供 `@pytest.mark.anyio`，讓 `async def test_...` 真的會被執行 |
| `testpaths = ["tests"]` | 直接打 `uv run pytest` 時只找 `tests/` 這個資料夾 |
| `markers = [...]` | 註冊 `browser` 這個標籤。不註冊的話 pytest 每次都會噴 `PytestUnknownMarkWarning` |

```python
"""pytest 共用設定。

A01 只放 anyio_backend；後面的篇章會往這裡加 fixture：
```

### Step 7：寫煙霧測試

新增檔案 `tests/test_smoke.py`，內容完整如下：

```python
"""A01 煙霧測試：確認現有骨架真的接得起來。

用 in-memory client（不開子行程、不走 stdio）連上 showme 的 MCPServer，
確認它剛好註冊四個 tool，而且沒有 wait_for_user。
"""

import pytest
from mcp import Client

from showme.server import mcp

pytestmark = pytest.mark.anyio

# design §7：Server 名稱 showme，只有這四個工具
EXPECTED_TOOLS = {"start_tutorial", "inspect_page", "show_step", "end_tutorial"}


async def test_server_exposes_exactly_the_four_tools():
    # docs/spec/features/開始教學.feature、顯示步驟.feature、檢查頁面.feature、結束教學.feature
    # 各對應一個 tool；多一個少一個都是契約壞掉
    async with Client(mcp) as client:
        result = await client.list_tools()

    assert {tool.name for tool in result.tools} == EXPECTED_TOOLS


async def test_server_does_not_expose_wait_for_user():
    # docs/spec/features/等待使用者.feature：
    # 「MVP 不提供 wait_for_user，顯示步驟改為畫出 overlay 後阻塞直到完成或逾時」
    async with Client(mcp) as client:
        result = await client.list_tools()

    assert "wait_for_user" not in {tool.name for tool in result.tools}
```

三個容易寫錯的地方：

1. `from mcp import Client`——是從 `mcp` 這個頂層套件 import，**不是** `mcp.client`。
2. `pytestmark = pytest.mark.anyio` 放在檔案最上層（不是函數裡），整個檔案的 async 測試就都會被執行。
3. `Client(mcp)` 傳的是 **server 物件本身**，這就是 in-memory transport。

預期看到紅燈，訊息大致長這樣：

```text
E       AssertionError: assert {'end_tutorial'... 'start_tutorial'} == {'end_tutorial'...'wait_for_user'}
E         Extra items in the right set:
E         'wait_for_user'

======================== 1 failed in 0.31s ========================
```

看到這個就對了——測試確實有去問 server 要 tool 清單。**把那行改回四個**，再跑一次 `uv run pytest`，回到 `2 passed`。

### Step 10：實測 tool 回傳 dict 時 `structured_content` 的形狀

官方文件說「字串鍵的字典不會被包成 `{"result": ...}`」（<https://py.sdk.modelcontextprotocol.io/v2/servers/structured-output>），但我們的註記是裸 `dict`。跑這一段確認實際結果——**這個答案 A14 寫契約測試時要用**：

```bash
uv run python - <<'PY'
import asyncio

from mcp import Client

from showme.server import mcp


async def main() -> None:
    async with Client(mcp) as client:
        result = await client.call_tool("inspect_page", {"session_id": "s_missing"})
        print("is_error           =", result.is_error)
        print("structured_content =", result.structured_content)


asyncio.run(main())
PY
```

**實測輸出（mcp 2.1.1，2026-08-29 實際跑出來的）：**

```text
is_error           = False
structured_content = None
```

兩件事一次確認完：

1. **`is_error` 是 `False`。** 目前四個 tool 都 `return {"error": "not_implemented"}`，不丟例外，所以 MCP 呼叫本身是成功的——這正是規格要的「失敗寫在 `error` 欄，不丟例外」（clarified：錯誤通道 B）。
2. **`structured_content` 是 `None`**——既不是裸 dict，也不是 `{"result": ...}`，而是**第三種**結果。

> ⚠️ **這裡跟原本的預期不一樣，A14 寫契約測試前一定要看這段。**
>
> 原因是**回傳註記寫成沒有參數的 `dict`**：mcp 2.1.1 產不出 output schema（`tool.output_schema is None`），沒有 schema 就沒有 `structured_content`。dict 的內容並沒有掉，它被序列化成 JSON 放在 `result.content[0].text` 裡：
>
> ```text
> content = [TextContent(type='text', text='{\n  "error": "not_implemented"\n}', ...)]
> ```
>
> 同一支 server 上三種註記的實測對照：
>
> | 回傳註記 | `output_schema` | `structured_content` |
> |---|---|---|
> | `-> dict`（我們現在的寫法） | `None` | `None` |
> | `-> dict[str, object]` | `{'additionalProperties': True, 'type': 'object', ...}` | `{'error': 'not_implemented'}`（就是那個 dict，沒被包） |
> | 完全不寫註記 | `None` | `None` |
>
> **所以 A07 改寫 `server.py` 時，要把四個 tool 的回傳註記從 `-> dict` 改成 `-> dict[str, object]`**，再跑一次這段確認 `structured_content` 變成 `{'error': 'not_implemented'}`。A01 不動 `showme/`，所以這件事留到 A07 做。

## 9. 常見問題與排錯

| 症狀 | 原因 | 怎麼處理 |
|---|---|---|
| `uv: command not found` | 沒裝 uv | macOS：`brew install uv`，或照 <https://docs.astral.sh/uv/> 的安裝指令 |
| `uv sync` 說找不到 Python 3.12 | 機器上沒有 3.12 | uv 通常會自己下載。真的沒動作就先 `uv python install 3.12` 再 `uv sync` |
| `uv sync` 之後 `import showme` 失敗 | 專案沒被裝進 venv | 確認 `uv sync` 輸出裡有 `+ showme==0.1.0 (from file:///...)`；沒有的話檢查 `[build-system]` 與 `[tool.hatch.build.targets.wheel]` 有沒有被刪掉 |
| `ImportError: cannot import name 'MCPServer' from 'mcp.server'` | 裝到 mcp 1.x（v1 API 叫 `FastMCP`） | `uv sync --upgrade-package mcp`，再確認 `m.version('mcp')` 是 2.x |
| `ImportError: cannot import name 'Client' from 'mcp'` | 同上，v1 沒有頂層 `Client` | 同上。v2 的 in-memory client 就是 `from mcp import Client` |
| 測試被跳過，訊息是 `async def functions are not natively supported` | 沒貼 `pytestmark = pytest.mark.anyio`，或 anyio 沒裝 | 檢查 `tests/test_smoke.py` 第一段有那一行；`uv run pytest` 的 `plugins:` 要看得到 `anyio` |
| `fixture 'anyio_backend' not found` | `tests/conftest.py` 沒建、或建錯位置 | 檔案要在 `tests/conftest.py`（不是根目錄，也不是 `tests/tests/`） |
| `PytestUnknownMarkWarning: Unknown pytest.mark.browser` | `markers` 沒寫進 `pyproject.toml` | 回 Step 3 補上 `[tool.pytest.ini_options]` 的 `markers` |
| `uv run pytest` 說 `no tests ran` | `testpaths` 指到空資料夾，或檔名不是 `test_*.py` | 檔名要是 `tests/test_smoke.py`；函數名要 `test_` 開頭 |
| `uv run playwright install chromium` 下載超慢或失敗 | 網路 | 重跑同一行即可（它會續傳／跳過已完成的）。這一篇後面用不到瀏覽器，卡住可以先往下做 A02、A03 |
| `uv run showme` 立刻結束並印 traceback | `showme/server.py` 或 `__main__.py` 被改壞 | `git diff showme/` 看有沒有誤改；這一篇不該碰它們 |
| `git status` 出現一大堆 `.venv/...` | `.gitignore` 沒生效（例如你在別的資料夾） | 確認 `pwd` 在 repo 根目錄，並 `cat .gitignore` 確認有 `.venv/` |
