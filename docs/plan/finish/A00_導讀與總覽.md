## 4. 名詞小抄

第一次做這種專案的人，先把這張表看一遍；後面每篇還會在自己的「名詞小抄」裡重講一次會用到的字。

| 名詞 | 一句白話 |
|---|---|
| **MCP**（Model Context Protocol） | 一套讓「AI 助理」跟「外部工具」講話的標準格式。我們寫的是被呼叫的那一端（server）。 |
| **stdio** | 標準輸入／輸出。我們的 server 不開網路 port，就是靠一支被啟動的程式，從 stdin 讀訊息、往 stdout 寫回覆。 |
| **tool** | MCP 裡「AI 可以呼叫的一個函數」。我們只有四個：`start_tutorial`、`inspect_page`、`show_step`、`end_tutorial`。 |
| **Qoder Agent** | 呼叫我們這四個 tool 的 AI。它會規劃步驟、挑 uid、寫給人看的說明。 |
| **Playwright** | 用程式控制瀏覽器的套件。我們用它開 Chrome、換頁、在頁面裡執行 JavaScript。 |
| **headed / headless** | headed＝看得到視窗；headless＝背景跑、沒有畫面。**Demo 一定要 headed**（人要看到箭頭）；**測試用 headless**（快、不干擾）。 |
| **init script** | Playwright 的 `add_init_script`：每次頁面建立或換頁時，**在頁面自己的程式跑之前**先塞一段 JS 進去。overlay 就是這樣進去的，所以 reload 後還在。 |
| **`expose_function`** | Playwright 的功能：在瀏覽器的 `window` 上掛一個名字，頁面呼叫它時，**實際執行的是我們的 Python 函數**。overlay 就是靠 `window.__showme_emit(...)` 叫醒 Python。 |
| **`window.__showme`** | overlay 掛在頁面上的物件，有 `snapshot` / `show` / `clear` / `done` 四個方法。A 只呼叫，不實作。 |
| **uid** | 元素的臨時代號，格式 `s{snapshot#}-{index}`，例如 `s1-4`。AI 只准用 uid 指元素，**不准寫 CSS selector**。 |
| **snapshot#（世代號）** | 第幾次拍頁面。每拍一次 +1，所以舊的 uid（`s1-*`）在新的一份（`s2-*`）裡一定找不到 → 逼 AI 重挑。 |
| **asyncio** | Python 的非同步框架：一個執行緒裡輪流跑很多「等待中的工作」，不用開多執行緒。 |
| **`async` / `await`** | `async def` 定義的函數叫協程；`await x` 的意思是「這裡會等，等的時候把 CPU 讓給別人」。 |
| **Future** | 「一個之後才會有答案的信箱」。`await future` 的人會睡著；別人 `future.set_result(答案)` 時，睡著的人就醒來。`show_step` 阻塞等使用者，就是在 await 一個 Future。 |
| **event loop** | asyncio 的排程器，負責在一堆協程之間切換。 |
| **pytest** | Python 最常用的測試工具。檔名 `test_*.py`、函數名 `test_*` 就會被自動找到。 |
| **fixture** | pytest 的「共用材料」。用 `@pytest.fixture` 定義，測試函數把它的名字寫成參數就會拿到。 |
| **marker** | 貼在測試上的標籤，例如 `@pytest.mark.browser`。可以用 `-m "not browser"` 挑掉不想跑的。 |
| **`conftest.py`** | pytest 自動載入的設定檔，放共用 fixture，不用 import。 |
| **測試替身（fake）** | 假的東西，長得跟真的一樣但不做真事。`FakeBrowser` 不開瀏覽器，`fake_overlay.js` 不畫箭頭，都是**只給 A 的測試用**。 |
| **TDD** | 先寫測試（看它紅）→ 再寫實作（看它綠）→ 再整理。每一輪 2～5 分鐘。 |
| **紅燈 / 綠燈** | 紅＝測試失敗；綠＝測試通過。 |
| **uv** | 這個專案用的 Python 套件與虛擬環境管理工具。所有指令都用 `uv run ...` 開頭，不用自己 activate venv。 |
| **`.venv`** | uv 幫你建的虛擬環境資料夾。**不進版控**（`.gitignore` 已經有 `.venv/`）。 |
| **`uv.lock`** | 鎖住每個套件的確切版本。**要進版控**，這樣兩個人裝出來的環境才一樣。 |
| **conventional commits** | commit 訊息格式：`feat:` 新功能、`test:` 加測試、`chore:` 雜事／設定、`docs:` 文件。 |

## 6. 介面約定

### 6.1 四個 tool 的簽名與回傳（`showme/server.py`，A07 之後長這樣）

```python
async def start_tutorial(url: str, goal: str) -> dict
async def inspect_page(session_id: str) -> dict
async def show_step(session_id: str, uid: str, instruction: str, kind: str,
                    step_index: int, step_total: int,
                    expect_text: str = "", timeout_s: float = 120) -> dict
async def end_tutorial(session_id: str, summary: str) -> dict
```

**回傳的鍵永遠都在**（成功時 `error` 是空字串，不是 `None`）：

```python
# start_tutorial
{"session_id": "s_8f2a", "goal": goal, "page": {...}, "next_action": "...", "error": ""}
{"session_id": "",       "goal": goal, "page": None,  "next_action": "",    "error": "navigation_failed"}

# inspect_page
{"page": {...}, "error": ""}
{"page": None,  "error": "session_not_found"}

# show_step
{"event": "step_done", "signal": "", "elapsed_s": 4.2, "page": {...}, "next_action": "...", "error": ""}
{"event": "",          "signal": "", "elapsed_s": 0.0, "page": None,  "next_action": "",    "error": "max_steps_exceeded"}

# end_tutorial
{"ok": True,  "error": ""}
{"ok": False, "error": "session_not_found"}
```

Page 的形狀（四個鍵固定）：

```python
{"url": "http://localhost:3000/", "title": "Dashboard",
 "elements": [{"uid": "s1-4", "role": "button", "name": "New Project", "testid": "new-project"}],
 "truncated": False}
```

**只准用這六個錯誤碼**（`docs/design/showme.md` §13）：

| error | 何時 |
|---|---|
| `navigation_failed` | `start_tutorial` 開不了 url |
| `session_not_found` | 沒有 Session（含 `end_tutorial` 成功之後）或 session_id 對不上 |
| `max_steps_exceeded` | `steps_shown >= 12` 還呼叫 `show_step` |
| `uid_not_in_snapshot` | uid 不在最新 page.elements（**回傳仍附新鮮 page**） |
| `expect_text_required` | 正規化後 kind 是 observe，但 `expect_text` 是空的 |
| `show_step_in_progress` | SHOWING 時再呼叫 `show_step`（第一個繼續等） |

`timeout` / `stuck` / `step_done` **不是錯誤碼**，是 `event`。

### 6.2 A/B 之間鎖死的名字（`docs/handoff.md`，任何人都不准改）

```text
A 在頁面裡呼叫（Python 用 page.evaluate）：
  window.__showme.snapshot(n)  → { elements: [{uid, role, name, testid}], truncated: bool }
  window.__showme.show({ uid, instruction, kind, index, total, expect })
  window.__showme.clear()
  window.__showme.done(text)

B 在頁面裡呼叫（每步恰好一次；A 用 expose_function 接）：
  window.__showme_emit({ kind: "step_done" | "stuck", url, ts })
```

- `uid` 格式 `s{n}-{index}`：**n 由 A 決定並傳進去**，B 只負責組字串。
- `show.expect` 就是 MCP 的 `expect_text`；`show.index/total` 就是 `step_index/step_total`。
- **timeout 由 A 在 Python 用計時器決定，B 不發 timeout。**

### 6.4 Session 狀態機

```text
                    （沒有 Session）
                          │  ▲
        start_tutorial 成功│  │ end_tutorial 成功（刪除 Session）
                          ▼  │
      ┌──────────────────────────────────────────┐
      │                READY                     │◀──────────┐
      │  可以：inspect_page / show_step /         │           │
      │        end_tutorial / start_tutorial      │           │
      └───────────────┬──────────────────────────┘           │
                      │ show_step：uid 通過 → 畫出            │ 收到 step_done / stuck
                      │            steps_shown +1             │ 或 elapsed_s >= timeout_s
                      ▼                                       │
      ┌──────────────────────────────────────────┐           │
      │               SHOWING                     ├───────────┘
      │  只等使用者；此時                          │
      │   ・第二個 show_step → show_step_in_progress
      │   ・inspect_page / end_tutorial → 失敗（A 的決定：也回 show_step_in_progress）
      │   ・start_tutorial → 仍可覆蓋（把卡住的那次收掉）
      └──────────────────────────────────────────┘

沒有 IDLE 物件（「IDLE」＝根本沒有 Session）；沒有 DONE 狀態（end 成功就刪掉）。
沒有 Session 時 inspect / show / end 一律 session_not_found。
```

### Step 4：TDD 的節奏（A02 開始每篇都這樣）

```text
  ①寫測試 ──▶ ②跑一次，看它紅 ──▶ ③寫最小實作 ──▶ ④跑一次，看它綠 ──▶ ⑤commit
     ▲                │                                    │              │
     │                │  紅得跟預期不一樣？                 │              │
     │                └─▶ 先修測試（可能是測試寫錯）        │              │
     │                                                     │              │
     └──────────────── 下一個行為 ◀────────────────────────┴──────────────┘
                              每一輪 2～5 分鐘
```

三個規矩：

1. **沒看過紅燈的測試不算數。** 一個從頭到尾都綠的測試，很可能根本沒測到東西。
2. **一次只加一個行為。** 不要一口氣寫十條測試再開始寫實作。
3. **紅燈訊息要看懂再往下。** 每篇都會寫出「這時候應該看到什麼錯誤訊息」，對不上就是哪裡不一樣。

### Step 5：跑測試的指令總表

| 想做的事 | 指令 |
|---|---|
| 全部跑一次 | `uv run pytest` |
| **只跑不開瀏覽器的**（平常最常用，最快） | `uv run pytest -m "not browser"` |
| 只跑會開瀏覽器的 | `uv run pytest -m browser` |
| 只跑某一個檔 | `uv run pytest tests/test_rules.py` |
| 只跑某一條測試 | `uv run pytest tests/test_rules.py::test_timeout_zero_becomes_the_default` |
| 名字含某個字的測試 | `uv run pytest -k timeout` |
| 第一個紅燈就停下來 | `uv run pytest -x` |
| 安靜模式（一行一個點） | `uv run pytest -q` |
| 看到 `print()` 的輸出 | `uv run pytest -s` |
| 手動啟動 MCP server（Ctrl+C 結束） | `uv run showme` |

> 所有指令都在 **repo 根目錄** 執行，而且都用 `uv run` 開頭——不用自己 `source .venv/bin/activate`。

### Step 6：commit 慣例

用 conventional commits，**一篇一到三個 commit**，而且只 `git add` 這篇動到的檔案（不要 `git add -A`）。

| 前綴 | 用在 | 例子 |
|---|---|---|
| `chore:` | 設定、依賴、工具 | `chore: pin python 3.12 and add dev dependencies` |
| `test:` | 只加測試（紅燈那一步） | `test: add session store behaviour tests` |
| `feat:` | 加產品功能（讓測試變綠那一步） | `feat: add Session dataclass and SessionStore` |
| `docs:` | 只改文件 | `docs: note the structured_content shape` |

實務上最順的做法是**紅燈與綠燈各一個 commit**：

```bash
git add tests/test_session.py
git commit -m "test: add session store behaviour tests"
# …寫實作，看到綠燈…
git add showme/session.py
git commit -m "feat: add Session dataclass and SessionStore"
```

## 9. 常見問題與排錯

| 症狀 | 原因 | 怎麼處理 |
|---|---|---|
| 不知道某個決定該聽誰的 | 文件有四層來源 | 優先序：`docs/spec/.clarify/resolved/` ＞ `docs/spec/erm.dbml` + `docs/spec/features/*.feature` ＞ `docs/design/showme.md` ＞ 這套計劃文件。發現計劃跟規格衝突，**以規格為準**並在合流時講一聲 |
| 想「順手」改 `overlay/overlay.js` | 那是 B 的檔 | 不要改。A 只需要它存在（`add_init_script` 用它的路徑）。要測 JS 呼叫，用 A06 寫的 `tests/fixtures/fake_overlay.js` |
| 想加一個 tool 讓事情簡單一點 | MVP 只有四個 tool | 不要加。`wait_for_user` 明確是 Non-Goal（`docs/spec/features/等待使用者.feature`） |
| 想在失敗時 `raise` | 例外會讓 MCP 把結果標成 `is_error` | 一律 `return` 一個 dict，把錯誤碼寫在 `error` 欄 |

| `uv run pytest` 很慢 | 混到了會開瀏覽器的測試 | 平常用 `uv run pytest -m "not browser"` |
| 找不到 `docs/plan/dev-prompts/phase0829.md` 說的東西 | 那是別的專案殘留 | 不要讀它 |
