## 測試方式

**TDD 節奏（測試先寫、先跑、再確認綠）：**

```text
寫 test_smoke.py  →  uv run pytest        →  2 passed（綠）
                  →  故意改壞 EXPECTED_TOOLS →  1 failed（紅）★ 確認它真的在測東西
                  →  改回來                →  2 passed（綠）
```

Step 9 的紅燈是這一篇唯一的紅燈，它的用途是證明「這條測試不是永遠會過的假測試」——它確實有去問 server 要 tool 清單。

**跑的指令：**

```bash
uv run pytest                                    # 全部
uv run pytest -m "not browser"                   # 平常用（本篇還沒有 browser 測試，結果一樣）
uv run pytest -W error::UserWarning              # 確認 browser marker 有註冊、沒有 PytestUnknownMarkWarning
uv run pytest tests/test_smoke.py::test_server_exposes_exactly_the_four_tools   # Step 9 單條
```

**Step 11 的驗證方式（跟計劃寫的不同）：** 這台 macOS **沒有 `timeout` 指令**（也沒有 `gtimeout`），所以沒辦法照 `timeout 3 uv run showme` 的寫法做。改用一支 Python supervisor：`subprocess.Popen(["uv","run","showme"])` → 等 5 秒 → 檢查 `poll() is None` → `terminate()`。這樣可以在不需要人按 Ctrl+C 的情況下，客觀證明「它起得來而且會阻塞」。

## 遇到的問題與怎麼解決

### 1.（主要）`structured_content` 是 `None`，不是計劃預期的兩種形狀

A01 Step 10 預期看到 `{'error': 'not_implemented'}`，並且說「如果看到 `{'result': {...}}` 就記下來」。**實測是第三種：`None`。**

追查過程——在一支拋棄式的 probe server 上放三種回傳註記，一次比對：

| 回傳註記 | `output_schema` | `structured_content` |
|---|---|---|
| `-> dict`（`server.py` 現在的寫法） | `None` | `None` |
| `-> dict[str, object]` | `{'additionalProperties': True, 'type': 'object', ...}` | `{'error': 'not_implemented'}` |
| 完全不寫註記 | `None` | `None` |

**原因**：mcp 2.1.1 是**從回傳型別註記推導 output schema** 的。沒有參數的裸 `dict` 推不出 schema（`_try_create_model_and_schema` 失敗），沒有 schema 就沒有 `structured_content`。

**dict 的內容並沒有掉**，它被序列化成 JSON 放在 `content[0].text`：

```text
content = [TextContent(type='text', text='{\n  "error": "not_implemented"\n}', ...)]
```

官方文件佐證（Context7，`/websites/py_sdk_modelcontextprotocol_io_v2`）：

- 「Return type annotations define the output schema published in the tool list.」
  <https://py.sdk.modelcontextprotocol.io/v2/servers/structured-output>
- 沒有可用註記時「Model creation failed or produced warnings - no structured output」
  <https://py.sdk.modelcontextprotocol.io/v2/api/mcp/server/mcpserver/utilities/func_metadata>
- 官方 dict 範例一律是**有參數的** `dict[str, float]`，不是裸 `dict`
  <https://py.sdk.modelcontextprotocol.io/v2/llms-full.txt>

**怎麼處理**：A01 明訂不碰 `showme/**`，所以**這一篇不改 `server.py`**。已把結論寫進 A01 Step 10，並標明 **A07 改寫 `server.py` 時要把四個 tool 的回傳註記從 `-> dict` 改成 `-> dict[str, object]`**。A14 寫契約測試前務必先看那一段。

### 2. 這台機器沒有 `timeout` 指令

`command -v timeout gtimeout` 兩個都沒有（macOS 預設不帶 GNU coreutils）。改用 Python `subprocess` supervisor 驗 Step 11，見上方「測試方式」。**A01 文件本身沒有叫人用 `timeout`**（它是叫人手動 Ctrl+C），所以文件不需要改。

### 3. 版本號跟計劃的範例輸出不同（不影響）

計劃範例寫 pytest 8.4.2，實際裝到 **9.1.1**；anyio 4.13.0 → 實際 **4.14.2**。`pyproject.toml` 寫的是 `pytest>=8`，都在範圍內，測試也全過。計劃本身就註明「版本號會不一樣」，不需要改。

`mcp` 是 **2.1.1**（2.x，符合硬性要求），`playwright` 1.62.0，Python **3.12.7**——三個關鍵的都對。

### 4. Step 3 的操作方式微調（不影響結果）

計劃說「把整個檔案換成下面這份」。我改成**在檔尾追加那兩段**，理由是原有五個區段本來就要一字不改，追加比整檔覆寫更不容易手滑。最終 `pyproject.toml` 內容與計劃給的完全一致。

### 5. A01 文件的兩個交叉引用編號錯了

- §1 寫「第 7 節 **Step 8** 會請你故意把測試改壞一次」→ 實際是 **Step 9**
- §6.3 寫「**Step 9** 會用一行指令實測」→ 實際是 **Step 10**

已一併修掉（各一個字）。
