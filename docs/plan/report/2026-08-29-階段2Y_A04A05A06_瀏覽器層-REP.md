## 實作邏輯

`showme/browser.py` 是 ShowMe 唯一碰瀏覽器的檔案，一層薄殼包住 Playwright async API。
它不認識 Session、不認識錯誤碼，只做「開瀏覽器 / 走頁 / 注入 / 呼叫頁面上的四個 JS 函式」。

```text
  Python（showme/browser.py）                       Chrome
  ─────────────────────────                        ───────────────────────────
  launch()
    chromium.launch(channel="chrome") ─┐ 失敗就 fallback 內建 Chromium
    new_context()                       │
      add_init_script(overlay_path) ────┼──▶ 每次 document 建立都先跑
      expose_function("__showme_emit") ─┘     ┌──────────────────────┐
    new_page()                                │ window.__showme      │
                                              │  snapshot/show/      │
  open(url) ─── goto ──────────────────────▶  │  clear/done          │
  snapshot(n) ─ evaluate("(n)=>...") ──────▶  │ window.__showme_emit │
  show(opts)  ─ evaluate("(o)=>...") ──────▶  └──────────┬───────────┘
  clear()     ─ evaluate("()=>...")  ──────▶             │
  done(text)  ─ evaluate("(t)=>...") ──────▶             │
                                                         │
  _on_emit(event) ◀──────── 頁面呼叫 emit ────────────────┘
    └─▶ self._emit_handler(event)     （A07 起由 ShowMeApp 用 set_emit_handler 登記）
```

三個關鍵設計：

1. **`BrowserLike` Protocol 一次寫完**（11 個方法）。它是契約不是實作，A07 的 `FakeBrowser`
   與 `app.py` 都照它寫，所以 A04 就把形狀鎖死，A05／A06 只是把 `PlaywrightBrowser` 補滿。
2. **`add_init_script` 與 `expose_function` 都掛在 Context 上，而且在 `new_page()` 之前**。
   掛 Context ⇒ reload／換頁後 `window.__showme` 與 `window.__showme_emit` 都還在；
   在 `new_page()` 之前 ⇒ 第一個分頁一開就有，不需要 reload 一次才正常。
3. **例外轉譯**：`open()` 把 Playwright 的例外轉成自己的 `NavigationFailed`，
   上層只要 `except NavigationFailed`，不必 import Playwright。錯誤碼 `navigation_failed`
   的字串是 A08 的事，不在這一層。

`PlaywrightBrowser` 最終 13 個成員，順序：
`__init__ → launch → _on_emit → is_alive → open → current_url → title → snapshot → show → clear → done → set_emit_handler → close`。

## 測試方式

- 全部瀏覽器測試都 `@pytest.mark.browser` + `headless=True`，檔頭統一
  `pytestmark = [pytest.mark.anyio, pytest.mark.browser]`。
- 測試頁不靠外部網路：`static_server` fixture 在 `127.0.0.1` 隨機 port 上送
  `tests/fixtures/pages/` 底下的靜態檔（session scope，整輪只起一次）。
- A05 用的是 **B 的 `overlay/overlay.js` stub**（只驗「注入成功」「reload 後還在」，
  不依賴 B 的實作內容）；A06 用的是 **A 自己的 `tests/fixtures/fake_overlay.js`**
  （靠建構子參數 `overlay_path=` 換掉），所以不用等 B。
- 兩條指令：`uv run pytest -m browser -q`（開 headless 瀏覽器）與
  `uv run pytest -m "not browser" -q`（平常用，最快）。
- **手動 headed 驗證**（S1／S2 的驗收是「用眼睛看」）：
  - `uv run python scripts/dev_open.py https://example.com` → 跳出真 Chrome 視窗、
    印 `opened : https://example.com/` 與 `title  : Example Domain`、10 秒後自關。
  - `uv run python scripts/dev_open.py http://localhost:1` → 印 `navigation_failed: ...`、`echo $?` 為 `1`。
  - A05 Step 5 的 DevTools 手動確認，改用一支 headed 腳本自動印出同樣的四項證據
    （避免 10 秒內手打指令來不及）：
    ```text
    before reload __showme: object
    after  reload __showme: object
    emit fn: function
    python received: [{'kind': 'step_done', 'url': 'http://127.0.0.1:8899/dashboard.html', 'ts': 1}]
    ```
    handoff「過了再分頭」的兩條都在**真的 headed Chrome** 上確認過，不只是 headless。

## 遇到的問題與怎麼解決

| 問題 | 原因 | 怎麼解決 |
|---|---|---|
| A04 Step 6 的預期輸出對不上：文件寫 `net::ERR_CONNECTION_REFUSED`，實際印 `net::ERR_UNSAFE_PORT` | Chrome 把 port 1 列在 unsafe port 清單裡，根本不去連，所以錯誤是「不安全的埠」而不是「連線被拒」。行為完全正確（`goto` 仍丟例外 → `NavigationFailed` → exit code 1） | 把 A04 §7 Step 6 那**一行**預期輸出改成 `net::ERR_UNSAFE_PORT`。其餘不動（文件本來就註明「訊息細節依 Playwright 版本略有不同，重點是前綴 `navigation_failed:`」） |
| 用 python 腳本改 `browser.py` 時，錨點 `    async def close(self) -> None:` 命中兩處 | `BrowserLike` Protocol 裡也有同名同縮排的宣告行 | 錨點加上下一行 `for closeable in (...)` 變成唯一，並在腳本裡 `assert count == 1` 先擋住，避免改錯地方 |
| 文件裡 `-m "not browser"` 的預期數字（`28 passed`）對不上 | A02／A03 由另一位 agent 平行進行，測試數會變動 | 不是錯誤，不改文件。只要「全綠 + deselected 數等於瀏覽器測試數」即可 |
| `SimpleHTTPRequestHandler` 會把每筆請求（含 favicon 404）印到 stderr | 預設行為 | 不處理。pytest 只在失敗時顯示 stderr，`-q` 下不影響判讀 |

**沒有踩到的坑**（文件預先提醒、實際照做就避開了）：`add_init_script` 寫在 `new_page()`
之後導致要 reload 一次；`page.evaluate` 用字串拼接導致 `instruction` 的引號炸掉；
`_on_emit` 寫成 async 導致 A12 的 `future.set_result` 出現競態。
