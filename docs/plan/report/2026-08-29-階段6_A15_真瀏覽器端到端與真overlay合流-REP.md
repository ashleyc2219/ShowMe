## 遇到的問題與怎麼解決

1. **主線 `show_step` 不能用預設 timeout。**
   A15 文件的 happy path 沒傳 `timeout_s`（等於 120 秒），一旦 emit 沒到就會被 pytest-timeout（60 秒）砍掉，
   看起來像整包卡死而不是斷言失敗。改成 `timeout_s=5`，失敗時 5 秒內就給出可讀的訊息。文件同步改掉。

2. **真 overlay 不能只等 `state is SHOWING` 就去點。**
   `app.py` 的順序是「先把 `session.state` 設成 `SHOWING` → 再 `await browser.show(...)`」，
   所以輪詢到 `SHOWING` 的那一刻，瀏覽器裡的 `show()` 可能一行都還沒跑。
   這時候 `page.click` 會在 overlay 掛上 `hashchange` listener 之前就把 hash 改掉，那一下不算，最後變 timeout。
   解法：再加一層 `_wait_for_highlight()`，輪詢 `document.querySelector('.driver-popover')` 出現。
   overlay 的 `show()` 是先 `driverObj.highlight()` 再 `observe()`，popover 進 DOM 就代表 listener 也掛好了。

3. **擔心 Driver.js 的遮罩會擋掉 `page.click`（結果沒有）。**
   Driver.js 會在 `<html>` 加 `driver-active`，配上 `.driver-active *{pointer-events:none}`；
   但同一份 CSS 也有 `.driver-active .driver-active-element{pointer-events:auto}`，
   而被高亮的正是 `Settings` 連結本身，所以 Playwright 的 actionability 檢查過得去，
   `page.click` 直接成功、`location.hash` 真的變成 `#settings`。不需要 `force=True`。

4. **真 overlay 的 banner id 和假 overlay 不同。**
   假 overlay 是 `showme-banner`，真 overlay 是 `__showme-banner`（`position:fixed` 的綠色橫幅）。
   所以真 overlay 那個檔改查 `document.body.innerText` 含不含 `DONE_BANNER_TEXT`，不去綁 id——實測 `innerText` 讀得到。

5. **A15 文件的 `_uid_of` 和 `_element_of` 重複實作同一段迴圈。** 直接讓 `_uid_of` 呼叫 `_element_of`，文件同步改。

6. **沒有遇到接縫不符，所以沒有任何 `xfail`。** 上一批報告提醒的「emit 多帶 `signal` / `uid` 兩個鍵」確實成立，
   但 Python 只讀 `event["kind"]`，多的鍵自然被忽略，回傳的 `signal` 照規格固定是 `""`，不用處理。

7. **`tests/conftest.py` 被平行的 A14 agent 改過（多了 `mcp_client` fixture）**，本階段完全沒動它；
   `tests/test_mcp_contract.py` 在本階段開始與結束時都是綠的。
