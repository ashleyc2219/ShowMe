## 實作邏輯

### `showme/session.py`（A02）

整包最底層的模組：**不 import 專案內任何其他模組**（只有 `asyncio`、`secrets`、`dataclasses`、`enum`）、不做 I/O、不碰瀏覽器。

- **四＋一個共用常數**：`MAX_STEPS = 12`、`DEFAULT_TIMEOUT_S = 120.0`、`DONE_BANNER_TEXT`（em dash，`✅ Done — you created a project`）、`START_NEXT_ACTION`、`STEP_NEXT_ACTION`。
- **`State(str, Enum)`**：只有 `READY` 與 `SHOWING`。刻意**沒有** `IDLE`（＝根本沒有 Session 物件）、**沒有** `DONE`（`end_tutorial` 成功就刪掉整個物件）。因為是 `str, Enum`，`State.READY == "READY"` 為真，序列化也不用另外處理。
- **`Session` dataclass**：`session_id` / `goal`（無預設，必須排前面）＋ `state` / `steps_shown` / `snapshot_no` / `latest_page` / `pending`（有預設）。`latest_page` 與 `pending` 的預設是 `None` 而不是 `{}`，否則 dataclass 會擋可變預設值。
  - `uids()`：從 `latest_page["elements"]` 抽出所有 `uid` 成一個 set，`latest_page is None` 回空 set。用 `if "uid" in element` 過濾，因為 `build_page` 遇到沒有 uid 的元素不會補假的，這裡不能 `KeyError`。
- **`new_session_id()`**：`"s_" + secrets.token_hex(2)` → `s_8f2a`（2 bytes = 4 個 hex 字元，用 `token_hex(4)` 會變 8 個字元而測試會紅）。
- **`SessionStore`**：內部只有一個 `Session | None`，**不是 dict**——規格說「同一 process 至多一個 Session」，用 dict 會讓「不小心存了兩個」變成可能。`get(session_id)` 在「沒有 Session」或「id 對不上」兩種情況都回 `None`（呼叫端據此回 `session_not_found`）；`delete()` 在沒有 Session 時也不能爆炸。

### `showme/rules.py`（A03）

六個純函數＋三個常數，同樣**不 import 專案內任何模組**（整份檔只有 `from __future__ import annotations` 一行 import）。

- `normalize_timeout_s`：`None` → `120.0`；先 `float(value)` 再判 `seconds <= 0` → `120.0`。判斷條件必須是 `<= 0` 而不是 `if not value`，否則 `0.2`（A12 等待測試要用）會被誤判成非法值換成 120，那條測試就會跑兩分鐘。回傳一定是 float。
- `normalize_kind`：不在 `KINDS` 白名單內（含 `None`、`""`、大小寫不同的 `"CLICK"`）一律 `"observe"`。**刻意不做 `.lower()`**：規格沒要求大小寫容錯，統一走 observe 行為更好預測，而且 `None.lower()` 會爆。
- `expect_text_missing`：先過 `normalize_kind`，所以非法 kind（例如 `"tap"`）也會套用 observe 的 `expect_text` 規則；observe 且 `expect_text` 是 `None` 或 `""` 時回 `True`。
- `build_page(raw, url, title)`：三件事——① 依 overlay 給的（＝DOM 走訪）順序取前 150 筆；② 每筆只留 `ELEMENT_KEYS` 四個鍵，缺的補 `""`，**但 `uid` 缺就不補**（uid 是 overlay 的責任，發明一個假的只會蓋住 bug）；③ `truncated = bool(raw.get("truncated")) or len(raw_elements) > MAX_ELEMENTS`——是 `>` 不是 `>=`，剛好 150 不算截斷。`raw.get("elements") or []` 讓 overlay 只回 `{}` 時不會 `KeyError`。
- `uid_in_page`：`page is None` 一律 `False`；用 `any(...)` 所以回的是真正的 bool。
- `empty_page()`：每次在函數裡 `return {...}` 建新的，不是模組層級常數，否則呼叫端改一份就污染全部。

**為什麼 `rules.py` 把 120.0 寫死而不 import `session.DEFAULT_TIMEOUT_S`**：為了讓純函數層完全不相依狀態層。兩邊走鐘的風險改由測試 `test_timeout_default_is_the_same_number_as_the_session_constant` 綁住——那條測試同時 import 兩個模組來比對。

## 測試方式

- 全部是**同步的普通 `def` 測試**：這兩個模組不碰 asyncio 事件迴圈、不開瀏覽器、不做 I/O，所以不需要 `pytestmark = pytest.mark.anyio`，也不需要 `@pytest.mark.browser`。
- 單檔跑：`uv run pytest tests/test_session.py`、`uv run pytest tests/test_rules.py`。
- 平常跑：`uv run pytest -m "not browser" -q`。
- 斷言風格照文件：布林值用 `is True` / `is False`（確認回傳的是真正的 bool，不是「剛好為真」的字串或數字）；物件同一性用 `is`（例如 `store.current() is session`，確認 store 沒有偷偷複製一份）。
- 有兩條「跨模組綁定」的測試，刻意讓未來的走鐘會紅：
  - `test_timeout_default_is_the_same_number_as_the_session_constant`：綁 `rules.normalize_timeout_s(0)` 與 `session.DEFAULT_TIMEOUT_S`。
  - `test_state_has_exactly_the_two_runtime_states`：綁死 `State` 只有 READY / SHOWING 兩個值，有人加 `DONE` 會立刻紅。

## 遇到的問題與怎麼解決

1. **A02 第二輪本來看不到紅燈。**
   A02 Step 3 已經把 `SessionStore` 一起寫進 `session.py` 了，所以 Step 5 補上 9 條 store 測試後直接就是綠的——這違反「沒紅過的測試不算數」。
   **處理**：照 A02 Step 5 文件裡自己提供的做法，暫時把 `SessionStore.get` 的 `if session is None or session.session_id != session_id:` 改成 `if session is None:`，跑出預期的紅燈：

   ```text
   FAILED tests/test_session.py::test_create_replaces_the_previous_session
   FAILED tests/test_session.py::test_get_returns_none_when_the_id_does_not_match
   E   AssertionError: assert Session(session_id='s_36d4', ...) is None
   2 failed, 17 passed
   ```

   確認「id 對不上要回 None」這條真的有被測到之後改回來，再跑一次 → `19 passed`。

2. **中途 `uv run pytest`（不加 `-m`）曾經整包 collection error。**
   訊息是 `ModuleNotFoundError: No module named 'showme.browser'`，來源是同時進行 A04 的另一個 agent 剛放進來、實作還沒補上的 `tests/test_browser_launch.py`。
   **處理**：不是本篇的責任，也不該去碰別人的檔。當下改用 `uv run pytest tests/test_session.py tests/test_smoke.py` 確認 A02 自己的 21 passed；等對方把 `showme/browser.py` 補上之後，整包就恢復正常了。這也是本篇一律用 `-m "not browser"` 驗收的原因。

3. **A02／A03 文件本身沒有需要修正的地方。**
   兩篇的指令、預期輸出、測試條數（19／32）、最終全綠條數都與實際完全相符，所以**沒有改動任何計劃文件**。唯一的細微差異是文件裡示範 traceback 的行號（例如寫 `tests/test_session.py:7`，實際是 `:8`），純粹是貼上去的示意輸出，錯誤訊息本身一字不差，不值得改。
